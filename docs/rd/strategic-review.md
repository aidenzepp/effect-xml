## Concerns and dispositions

Each concern names the present commitment, the future pressure, the affected boundary, an owner, and a recheck. `correct_before_next_phase` here means before the named M1 units are dispatched; nothing is implemented, so the corrections are planning edits.

### C1. `suspend` members in a `mixed` union are never indexed; the issue shape M1-U09 assumes is wrong for recursive XHTML bodies

- Disposition: **correct_before_next_phase** (before M1-U03 and M1-U09 dispatch). Severity P1 if missed: wrong-looking errors on the most common XHTML shape, which is exactly what T3 was ruled to prevent.
- Evidence: `getCandidateIndex` computes each member's candidate with `toCandidate` (`SchemaAST.ts:3527`); `toCandidate` returns `unknown` for a `Suspend` before any sentinel is read (`:3391`), and `collectSentinels(unknown)` is empty, so the member joins `otherwise` for every runtime type (`getCandidateTypes`). Fallbacks are "never removed by sentinel checks" (`:3602`) and candidates run in index order with the first success winning (`:3647`, `parseUnion`). The benchmark vocabulary nests `div` through `suspend("div", () => Div)` inside `mixed([P, suspend(...)])` (`spikes/declaration-dsl/benchmark-b.ts:92`; M1-U15 copies it), and `bg010-missing-word.xml` puts its `<p>` with the inline interaction under `div` and `blockquote`.
- Consequences on the plan as written: (1) under any union holding a `suspend` member, a failure inside a declared member yields an `AnyOf` with the declared member's issue **and** the suspend member's name-mismatch issue, so M1-U09's "collapses to its single selected member's issue" meets two; (2) an unknown child under such a union yields an `AnyOf` with one issue (the suspend member's), not the zero-issue `AnyOf` phase-4 lock 4 keys its second case on; (3) decode still succeeds for valid input (the matched member or the suspend member wins), so M1-U03's R2 recheck as written, which has no `suspend` member, would pass and prove nothing about this.
- Correction (Planner; `phase-1.md` M1-U03 and M1-U09, `phase-1.slices.md` m1-10, m1-22, m1-23; `phase-4.md` lock 4 and M4-U04 shrink accordingly): M1-U09's `AnyOf` rule becomes the general one phase-4 lock 4 already states for the guard: at a `mixed` index whose input is an element, keep the issue of the member whose `Plan` name equals the element's Clark name and drop the rest; when no member matches, emit one issue naming the child's Clark name and the member set. M1-U03's R2 recheck adds a `suspend` member to the union and asserts the declared member's leaf issue is present (one leaf per declared member, plus the suspend member's mismatch, which U09 drops). M1-U04 and the vocabulary note that `suspend` members are tried as fallbacks and are cheapest declared last in `mixed` (one failed `name` literal check per child when they precede the matched member). M2-U07 (c) is unaffected (`qti-item-body` has no `suspend` member) and gains a sibling case under `div`.
- Boundary: `compile`, `issue`. Recheck: M1-U09 done_when includes a bad attribute under `div > blockquote > p` producing one translated issue.

### C2. The C1 criterion proof must compare against the input tree

- Disposition: **correct_before_next_phase** (before M1-U15 dispatch). Severity P2 (a gate test that cannot fail on the defect it guards).
- Evidence and reasoning: ruling (d), second half. The seam M1-U03 copies writes `elements` children in slot order (`element-codec.ts:272-281`); value deep-equality after a second decode is blind to a slot-order difference that canonical equality against the input catches.
- Correction (Planner or slicer; `phase-1.slices.md` m1-33 and m1-34 briefs, `phase-1.md` M1-U15 done_when wording): `test/qti/vocabulary.test.ts` obtains the input tree with `resolveEvents` and `collect(["*"])` imported from `../../src/resolve.ts` (test-side, exactly as M1-U14 does) and asserts `canonicalize(input, { inline: inlineNames(Def) }) === canonicalize(Schema.encodeEffect(Def)(value), ...)`. `vocabulary.ts` stays consumer-shaped and nothing new is exported.
- Boundary: `test/qti/`. Recheck: the M1 verify gate shows the canonical assertion in the vocabulary suite.

### C3. `elements` mode's encode order is not in the round-trip exclusion list

- Disposition: **record_risk**, applied to D1 in `decisions.md`; findings for the Planner (`GOAL.md` "Constraints And Invariants" exclusion list; `phase-4.md` M4-U08 exclusion bullets and the `for t in ...` check gains the term `slot order`).
- Present commitment: named fields cannot hold cross-name order; encode writes declared slots in declaration order (M4 lock 2 extends this to the `"*"` slot).
- Future pressure: a consumer vocabulary over an `xs:all` group or a document that is valid but not in sequence order round-trips to a canonically different tree. R3 (order validation on decode) is the sibling risk; this is the encode side of the same fact.
- Owner: Planner (docs); the README Hand (M4-U08). Recheck: the README exclusion loop prints no `0` for the new term.

### C4. Per-record metadata lives in a `WeakMap` side table keyed by element identity

- Disposition: **record_risk** (R11).
- Present commitment: phase-3 lock 7 keeps `collect`'s output type `ResolvedElement` and parks the position tree in a module-level `WeakMap` exposed as `recordPositions(element)`. Lifetime-safe, invisible in types, and a containment facade for a type the design refuses to widen.
- Future pressure: `xsi:type` (R10) needs each element's in-scope prefix map at decode time; the resolved `StartElement` already carries `scope` and the collector drops it. That is a second per-record tree hanging off the same key.
- Ruling: one side table is acceptable for M3. The moment a second one is wanted, replace the `WeakMap` with an internal record envelope emitted by `collect` (`{ element, positions?, scope? }`), consumed by the codec and never exported; do not add a second `WeakMap`. The public `ResolvedElement` does not change.
- Why not correct now: the envelope touches M1-U11 and M1-U14 call sites and three admitted specs for a need (`xsi:type`) the owner has not asked for; the cost is constant until that need arrives, so it is not cheaper today.
- Boundary: `resolve`, `codec`. Owner: Planner at R10 time. Recheck: any unit that proposes a second side table.

### C5. The public `elementPath` field carries an internal indexing convention

- Disposition: **record_risk** (R12).
- Present commitment: reasons `Schema` and `UndeclaredPrefix` carry `elementPath: ElementPath` (zero-based, positional among element children, local names) beside `path` (one-based, same-named siblings, XPath print). The phase-2 done_when itself exhibits the divergence: `path` says `p[2]` while the last step is `{ p, 2 }` or `{ p, 3 }` depending on preceding element children.
- Future pressure: publish freezes the name; a later structured path for consumers (segments of Clark names with the XPath indices) would want the name `elementPath`.
- Ruling: before the package leaves `private` (M4 close), decide once: rename the field and the exported type to say what it is (`locator: ElementLocator`), or demote it to an internal carrier (the resolver and translator hand the locator to the codec beside the error; the public reasons stay M1-shaped). Either is a word-level change in `phase-2.md`, `phase-2.slices.md` (m2-7, m2-8, m2-9), and `phase-3.md`, and the want `4854001b` is the natural touch to fold the rename into. Not a `correct_before_next_phase` item because the package is unpublished and the rename costs the same until it is.
- Boundary: `issue`, `codec`, `src/index.ts` type exports. Owner: Planner. Recheck: M4-U08, before the README names the error shape.

### C6. `src/resolve.ts` is the cross-milestone hot module

- Disposition: **record_risk** (R13), with an option the build Mind may take without reopening a ruling.
- Present commitment: M1-U06, U07, U08, M2-U05, M3-U03, M3-U07 all write `src/resolve.ts`; each milestone's `resolve.ts` unit waits for the previous milestone's last writer by file, not by data (M3-U03's budgets need nothing from M2-U05's locator counter).
- Future pressure: M2 and M3 serialize behind one file; the file itself grows to four responsibilities (resolver, collector plus budgets, position forwarding, encode prefix chooser).
- Option: D11 allows the Planner to add a module ("add a module, do not merge two"). Splitting the collector and its budgets into `src/collect.ts` at M1-U07 (M1-U08 keeps `resolve.ts` for the encode side) lets M3-U03 proceed beside M2-U05 and halves the hot chain. The cost is a recut of M1-U07/U08 scopes and slices m1-18 to m1-21 plus the M2/M3 edges that name the file; not required for correctness.
- Owner: build Mind (decision), Planner (recut). Recheck: when M3 src units are READY while M2-U05 has not landed.

### C7. Clark-name allocation in the resolver

- Disposition: **proceed**, implementation note for the M1-U06 Hand (doc comment and a one-line test is enough).
- The resolver builds the Clark string for every start element and every attribute key; without interning, a 300,000-element tree-mode document holds 300,000 fresh 60-character strings for the same dozen names. A per-run cache keyed by as-written name within the current scope (invalidated when the scope frame changes a binding) returns one string object per distinct expanded name. This also gives the resolver the natural place to stamp the as-written `size` ruling (b) needs. Recheck: the `node-budget:` and `streaming:` lines M3-U02 and M3-U10 print.

### C8. The `open` guard

- Disposition: **proceed**. The auditor's source verification (`SchemaAST.ts:3602`, `:3613`, `:3647`, `:3904`) is confirmed by this read; the guard member's encoded `Struct` has no literal `name`, so it is an object fallback and is appended last. One addition from C1: a union with both a `suspend` member and the guard has two fallbacks, tried in declaration order; the guard stays last, and M4-U04's name-match rule is the same rule C1 pulls into M1-U09.

### C9. Error class kind

- Disposition: **proceed** with a recommendation. m1-13 leaves `Schema.TaggedError` versus `Data.TaggedError` for the two cause-bearing reasons to the implementer. Prefer the outer `Schema.TaggedError` with `Schema.declare` guards for the causes (the guide's reason pattern), so `XmlDecodeError` stays schema-describable end to end; that keeps a later serialisation or RPC surface free. The `consequences` lens on M1-U05 is already assigned.

### C10. Upstream feature request

- Disposition: **proceed**, no plan dependency. The preview is well-formed and the third hater pass's blocking points are the maintainer's likely replies (no named consumer; start-tag-only shape; the shared `StartElement` type). Strategic read: the request is stronger after M2 and M3 land, when the two-source design is shipping code and the measured cost is the library's own; filing is the owner's call and nothing here waits on it.

### C11. Unit graph serialization and hot modules

- Disposition: **proceed**. M1's eight-unit chain (`U01 → U02 → U03 → U09 → U11 → U12 → U15 → U16`) is data-forced: element type, IR, compiler, translator, operations, entry, vocabulary, error proofs. M1-U09's edge on U03 is a test dependency (compiled definitions in the translator tests), acceptable. M2's chain of five and M3's of six are likewise forced (locator type before the reason field before the resolver counter before the codec wiring; measurement before the default constant before the stream operation). No false edge found; the one hidden cost is the file-level coupling in C6. Shared files are serialized by recorded edges everywhere (`resolve.ts`, `issue.ts`, `codec.ts`, `index.ts`, `positions.ts`, `test/upstream-xml.test.ts`), and the slicer's chain of 18 at 5 to 10 minutes each is a short critical path. The milestones themselves serialize on shared files: only M3-U02, U04, U05 can start before M2's `src/` writers land.

### C12. Framework and layer check

- Disposition: **proceed**; nothing unearned. Checked: the `Plan` (closed, private, one producer); the `effect-xml` marker (one annotation key, three fields); `namespaces(map)` returning bound constructors (no facade); the per-element `decodeTo` (one Schema feature used as designed); the guard (`Schema.makeFilter`, public); `inlineNames(def)` plus the raw-tree name set in `canonical` (two inputs, one comparator); the position channel and `locate` (two sources, licensed by one agreement test, with the upstream request as the exit); `PositionTree` and `positionAt` (M3) as `locate` over a tree, small and internal; the runtime-neutral GC helper (test-side). The only thing that reads as a layer is the `WeakMap` registry in C4, and it is recorded.

# Effect 4.1.2 substrate map for an XML Schema codec

Research record for the effect-xml R&D campaign (task `dc935e47`, head-cto). It states what the pinned `effect@4.1.2` already gives a typed XML codec, where each piece stops, and which extension seams are real. It does not design the library.

Every path below is relative to `node_modules/effect/src` at `effect@4.1.2` (the version in `package.json`). Facts marked **probed** were also confirmed by running a script against the installed package with `bun` (scripts were transient; the shapes are described in section 5).

## 2. Extension seams

1. **Attach XML metadata to a schema.** Real, two ways. (a) Custom annotation keys on `ast.annotations` via `.annotate({...})`, with `declare module "effect/Schema"` augmentation for typing (`Schema.ts:19089-19098`). Read them from `ast.annotations` directly, not through `resolveAnnotations`, because checks shadow it (section 1.3). Use `annotateKey` (`Schema.ts:752`) when the metadata belongs to the field position (element vs attribute, wire name) rather than the value type; it lands in `type.context.annotations` and survives field reuse. (b) `Schema.declareConstructor` (`Schema.ts:524`) for an opaque wrapper node whose `run` decodes a materialised value and whose `toCodecStringTree` hook (`Schema.ts:19283`) re-encodes it. There is no custom AST node kind (`SchemaAST.ts:54-75` is closed).

2. **Walk a schema generically.** Real. Switch on `ast._tag` over the public fields: `Objects.propertySignatures` / `indexSignatures` (`SchemaAST.ts:2831-2832`), `Arrays.elements` / `rest` (`:2310-2311`), `Union.types` (`:3693`), `Suspend.thunk` (`:4003`), `Declaration.typeParameters` (`:747`), and each node's `context.isOptional` (`:627`) and `encoding` (`:691`). `SchemaBinary` does exactly this (`encoding/SchemaBinary.ts:2213-2233`, `:2441`), including walking `SchemaAST.toEncoded(ast)` for the wire side. Keep Type-side and Encoded-side walks distinct: annotations live on the Type side, string leaves on the Encoded side. `recur`/`flip`/`getParser` on nodes are `@internal` (`SchemaAST.ts:2834-2846`); `SchemaAST.toEncoded`, `flip`, `decodeTo` are public (`:4775`, `:4815`, `:4591`); `annotate`, `replaceEncoding`, `mapLink`, `applyToSelfOrLastLinkEncodingIdempotent` are `@internal` (`:4399`, `:4377`, `:4424`, `:4455`).

3. **Typed decode failures with a path.** Real for the path, absent for positions. Emit `new SchemaIssue.Pointer(path, leaf)` (`SchemaIssue.ts:413`) with XML-shaped segments and wrap in `Schema.SchemaError` (`Schema.ts:1219`); the default formatter prints `at [...]` (**probed**). Line and column exist only on `XmlError` from the decoders (`Xml.ts:1037-1045`) and are lost by `elements` (`:1793-1794`). A codec that wants positions on schema failures must carry them itself (for example into `InvalidValue.annotations.message`, or in a wrapper error that pairs an `Issue` with a position) because `Issue` has no slot for them (`SchemaIssue.ts:156-163`).

4. **Drive a schema from an event stream.** Not available as a parser input. `SchemaParser.Parser` takes one `unknown` value (`SchemaParser.ts:1199-1204`) and `Declaration.run` likewise (`SchemaAST.ts:720-722`). The incremental seam is at the channel level: `Xml.elements` yields one materialised `Element` per matched record (`Xml.ts:438`), and `ChannelSchema.decode` decodes each chunk (`ChannelSchema.ts:103-118`). So "streaming" means per-record streaming over a root-anchored path, then value decoding; it does not mean a schema-driven pull parser. Building one would be new code on `Channel.fromTransform` (`Channel.ts:294`) and `Pull.matchEffect` (`Pull.ts:438`), the same pattern as `Xml.ts:568-616`.

5. **Bidirectional string leaves.** Real. `Schema.toCodecStringTree` (`Schema.ts:18441`) is a codec, not just an encoder: it decodes `"3"` to an `Int` and fails on `"3.5"` with a path (**probed**). It already covers `Class` (via the `toCodec` hook at `Schema.ts:17520-17521`), `Boolean`, `Null`, `Number`, `Literal`, `Enum`, and `Union` reordering. It is the natural substrate for attributes and text content; what it cannot express is section 3.

6. **Channel composition.** Real. `Stream.pipeThroughChannel` (`Stream.ts:16246`), `Stream.decodeText` (`:16877`), `Stream.mkString` (`:20069`), `Stream.runCollect` (`:19384`), `Channel.fromTransform` (`Channel.ts:294`), `Channel.map` (`:2112`), `Channel.pipeTo` (`:9296`). Xml channels are chunk-to-chunk with a synchronous machine, so a third-party event-to-events channel can follow `makeChannel` (`Xml.ts:568-616`).

| Distinguish element **name** from record **key** (wire name, prefix)               | `Objects.propertySignatures[].name: PropertyKey` (`SchemaAST.ts:2661-2663`), `toEncoderXml.ts:79`                                                    | The key is the tag name after sanitising; no annotation or field redirects it.                                                                                                                                                                        |
| **Namespace** resolution (prefix to URI, default namespace, `xml:` prefix)         | `Xml.decodeString` gotchas (`Xml.ts:301-302`), `StartElement` (`:133-137`), `isName` (`:680-707`), `Collector` matching (`:1744-1746`)               | Names are opaque strings; `xmlns*` are ordinary attributes; `elements` paths compare qualified-name strings. Nothing maps prefixes to URIs or equates `a:x` with `b:x` bound to the same URI.                                                         |
| Source **position** on a schema failure                                            | `SchemaIssue` node types (`SchemaIssue.ts:111-163`), `ParseOptions` (`SchemaAST.ts:507-599`), `Xml.elements` errors (`Xml.ts:1791-1796`)             | `Issue` has no position field and parse options cannot inject one; positions stop at the event stream.                                                                                                                                                |
| Schema-driven **incremental** parsing                                              | `SchemaParser.Parser` (`SchemaParser.ts:1199-1204`), `Declaration.run` (`SchemaAST.ts:720-722`), `ChannelSchema.decode` (`ChannelSchema.ts:103-118`) | All take materialised values. ## 4. Risks for the owner goal

Severity: P0 wrong product or data loss, P1 significant rework, P2 nit.

| Risk                                                                             | Severity                                                               | Present fact                                                                                                                                                                                                                                                             | Smallest producer fact that settles it                                                                                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **One definition, both directions** built on `toEncoderXml` would be a dead end. | P1                                                                     | `toEncoderXml` cannot emit attributes, has no decoder, does not share `encoding/Xml`'s event model or escaping (section 1.2). A design that extends it inherits all three limits.                                                                                        | A spike that encodes one QTI `assessmentItem` to events with `Xml.encodeString` from a schema-driven walker, and decodes the same via `Xml.elements` + a StringTree-style value decoder, proving the shared definition without `toEncoderXml`. If that works, `toEncoderXml` is a non-goal, not a base.             |
| **Typed `data-*` and other attributes.**                                         | P1                                                                     | Attributes arrive as `Record<string, string>` (`Xml.ts:136`); `toCodecStringTree` already decodes string leaves into typed values with pathed failures (**probed**). Risk is the number leaf: `NumberFromString("x")` succeeds as `NaN` (**probed**, `Schema.ts:10288`). | A probe that decodes `data-count="x"` through the chosen attribute codec and asserts a failure; the fix is to default attribute numbers to `FiniteFromString` (`Schema.ts:10317`) or `Finite` checks, and to state that in the design.                                                                              |
| **Mixed content** has no StringTree shape.                                       | P0 if the library targets StringTree as its encoded form; P1 otherwise | `Tree` cannot interleave text and named children (section 3). `Element.children` can (`Xml.ts:231`).                                                                                                                                                                     | A decision on the encoded intermediate: `Xml.Element`-shaped (ordered `children`) versus `StringTree`. Verifying that a `Schema.declareConstructor` wrapper over `Element` with a `toCodecStringTree` hook is _not_ needed for the owner's intermediate would settle whether StringTree is in the path at all.      |
| **Namespaces** are strings, not bindings.                                        | P1                                                                     | `xmlns`/`xmlns:p` are ordinary attributes; `elements` paths compare qualified names (`Xml.ts:1744-1746`). QTI fixtures mix a default XHTML namespace and a `qti:` prefix (**probed** event dump).                                                                        | A spike that resolves in-scope bindings from `StartElement.attributes` while walking events (a small stack), and shows two fixtures using different prefixes for the same URI decode to the same value. That proves namespace handling is library work on top of the parser, not a parser gap that blocks the goal. |
| **Round trip** meaning.                                                          | P2                                                                     | Byte-identical round trip is unattainable through `Xml.encode` (section 3); equivalent round trip is stable (**probed**).                                                                                                                                                | Operator or Mind ruling that "round trip" means equivalent XML (same events), recorded in `docs/onboarding.md`'s open decisions.                                                                                                                                                                                    |
| **Failure positions.**                                                           | P1                                                                     | Schema issues cannot carry line/column (section 2.3); `elements` drops positions (`Xml.ts:1793-1794`). A decode error on a 2 MB QTI item that says `at ["qti:itemBody"][12]["p"]` without a line is weaker than the owner's "Zod for XML" bar implies.                   | A probe that keeps `(line, column)` per `StartElement` in the event walker and attaches it to the pathed issue (message text or a wrapper error). If that is cheap in the spike, make it a requirement; if not, record the limitation.                                                                              |
| **Annotation visibility.**                                                       | P2                                                                     | `resolveAnnotations` returns the last check's annotations (`internal/schema/annotations.ts:6-8`), hiding codec metadata set before `.check()`; Type-side annotations do not reach `toEncoded` (**probed**).                                                              | A single rule in the design: the codec reads `ast.annotations` and `ast.context.annotations` on the Type-side walk and never through `resolveAnnotations`.                                                                                                                                                          |
| **Upstream stability.**                                                          | P2                                                                     | `encoding/Xml` is `@stability experimental` (`Xml.ts:16`); `Schema.toCodecStringTree` is stable (`Schema.ts:18437`); `ChannelSchema` is unstable (`ChannelSchema.ts:8`); `SchemaCompiler.set` is unstable (`schema/SchemaCompiler.ts:12`).                               | Keep `test/upstream-xml.test.ts` as the canary and extend it with the event shapes this map relies on (whitespace `Text`, prefixed names, `elements` child order).                                                                                                                                                  |
